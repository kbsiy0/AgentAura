# 中英雙語切換（change `i18n`）

2026-09-14。使用者要求：「做一下繁體中文版跟英文版的切換，然後預設是英文版的」。

## 1. 現況規模（實測，非估計）

| 項目 | 數量 |
|---|---|
| 生產碼中文字串字面 | 約 107 個，散在 18 個檔 |
| 其中在 `AuraCore` | 約 90（`InstallAffordance` 21、`PanelViewModel` 16、`OptionsMenuModel` 15、`PanelModel` 9、`Jargon` 9…） |
| 其中在 `AgentAuraApp` | 約 17 |
| **測試裡斷言中文字面的條數** | **約 46 條，散在 12 個測試檔** |
| `Resources/help.html` | 279 行，需要英文版 |

## 2. 決策

**D-1 機制：`AuraCore` 裡一份 enum 鍵的字串表，不用 `.strings` / `String(localized:)`。**
- `AuraCore` 不得載入 Foundation 閉包以外的任何 module（既有 invariant），`.lproj` 資源那條路走不通。
- **窮盡 switch 讓「少翻一個字串」變成編譯錯誤**。`.strings` 檔漏翻是靜默的——這個 codebase
  已經被手維護清單咬過兩次（`EventMapping` 漏註冊 `Elicitation`、`SessionsCardSizing` 凍住錯的列高），
  gate 哲學第 2 條明文要求從型別推導。型別系統本身就是這裡最好的 gate。
- 執行期切換只是換一個參數，不必操作 bundle，離屏完全可測。

**D-2 預設英文，不跟隨系統語言。** 使用者明講「預設是英文版」。中文系統上第一次啟動也是英文。

**D-3 語言是顯示層的參數，不是全域狀態。**
字串表的查詢帶語言參數；`PanelModel.make` 等既有工廠多吃一個 `language`。
**不要**用全域單例或 `static var currentLanguage`——那會讓測試互相污染，也讓「同一份 model
兩種語言渲染」變得不可測。偏好值只住在 composition root（`AppDelegate`），往下傳。

**D-4 既有 46 條中文斷言：明確要求中文，不改斷言內容。**
那些斷言（例如「這一列說得出『背景』」）測的東西仍然成立，只是現在要指定語言。
**這是對齊新契約，不是弱化**——判準是「測的還是同一件事嗎」，是。
逐條在 PR 說明。**不得**把它們改成比對 key 而不比對文字：那會讓「翻譯內容錯了」變成測不到。

**D-5 新增的 gate（英文那半的防線）**
1. **窮盡性**：由 enum + 無 `default` 的 switch 在編譯期保證，不需要 runtime gate。
   但要有一條測試證明**確實沒有 `default` 分支**（否則有人加 `default` 就破功）——用來源掃描。
2. **兩種語言不得相同**：每個 key 的中英文若字面相同，多半是忘了翻。允許例外（產品名、版本號、
   `⌘Q` 這類），例外要**明列**並說明理由，不得用「全部略過」。
3. **沒有漏網的字面**：掃 `Sources/`，任何含中日韓統一表意文字的字串字面都必須出現在字串表裡，
   不得散落在其他檔案。這條擋的是「新功能又寫死一句中文」。
4. **預設是英文**：composition root 的 smoke 斷言未設定偏好時拿到的是英文。

**D-6 `help.html` 出英文版**，隨 `build-app.sh` 一起進 bundle，依語言選檔。
既有 `HelpDocOptionsRowCoverageTests`（說明文件必須涵蓋每一個 Options 列）要**兩個語言版本都守**。

實作（T30）：檔名規則 `Resources/help-<Language.rawValue>.html`（`help-english.html` /
`help-traditionalChinese.html`），`AppDelegate.helpResourceName(for:)` 是這條規則的純函式
版本；`scripts/build-app.sh` 用 `Resources/help-*.html` glob 複製，跟 Swift 那側各自從
「檔名規則」這同一個來源推導要處理哪些語言，不互相手抄清單——加第三語言只需要多放一個
對應檔名的資源檔，兩邊程式碼都不必改。

**D-7（known gap）：「關於」面板的版權行固定英文，不隨面板顯示語言切換。**
查過 AppKit 標頭（`NSApplication.h`）：`NSAboutPanelOptionKey` 只定義五個鍵——
`Credits`／`ApplicationName`／`ApplicationIcon`／`Version`／`ApplicationVersion`，
沒有 `Copyright` 這個覆寫點。Standard about panel 的版權行只能從**執行中 bundle 的
`Info.plist`**（`NSHumanReadableCopyright`）讀，`AboutContent.options(version:)` 這個
`options` 字典無從覆寫（`AboutContentTests` 的既有註解已經記過這件事，T13 附帶發現）。

Info.plist 這類資源要在地化，AppKit 的機制是 `InfoPlist.strings` ＋ `.lproj`
資料夾——但那條路是**跟隨系統語言**，跟 D-2「預設英文、使用者可在面板手動切換」的
`language` 偏好是兩條不同的軸：中文系統上使用者可能把面板語言切成英文，卻仍然拿到
中文版權行（或反過來），變成「一致地跟系統走」與「一致地跟面板走」兩者都做不到、
只能選一邊。**裁決：固定英文**——「永遠英文」是一種一致的狀態；「隨系統語言，
可能跟面板顯示語言對不上」不是一致的狀態，反而更容易讓人以為是 bug。這一行的
內容本身也無關痛癢（版權尚未決定），不值得為了雙語切換另外導入 `.lproj` 機制。

## 3. 不做

- 不做第三種語言的擴充機制（YAGNI）。enum 加一個 case 就能長，不需要先抽象。
- 不做系統語言偵測。
- 不做已落盤內容的翻譯（狀態檔裡的 `last_message` 是 Claude 自己的輸出，不是我們的文案）。
