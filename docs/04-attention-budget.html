二、注意力預算：我原本的設計是錯的

你的常態是多 agent 併行、整夜跑 pipeline。在這個常態下，把 working 設成跑動的 comet 意味著 menu bar 幾乎永遠在動 —— 而一直在動，「動起來」就失去了訊號價值，你必須辨色才知道發生了什麼事。這正是 前一個專案 太吵的同一個病。

原設計 · 3 個 session 都在 working

19:34
常態就長這樣，一整天都在跑
✕ 一直在動 → 「動」不再代表任何事

新設計 · 同樣 3 個 session 都在 working

19:34
看得出在跑，但不搶注意力（4s 週期、低對比）
✓ 安靜 → 一動起來就是「需要你」

改成「動 = 需要你」之後得到三件事：常態安靜不干擾；餘光就能判斷，不需辨色（單一、無歧義的規則）；大多數時間零重繪，電池成本趨近於零。

五個狀態的新呈現（都是活的）

idle無動畫 · 近乎不可見
working（常態）極慢呼吸 4s · 低對比
done恆亮 · 無動畫
waiting（需要你）明顯呼吸 1.1s
error（需要你）double blink

一個對你原始需求的重新解讀，需要你確認。你最初說「icon 有明顯的識別作用、甚至是動畫，可以看到 AI 的運行狀態」。新設計把動畫預算幾乎全部讓給「需要你」的狀態，working 只剩極慢極淡的呼吸。你仍然看得出 AI 在跑（相對 idle 有明顯亮度差），但那不再是搶眼的動畫。如果你要的是「跑起來就要看得出很活躍」，那要走回原設計 —— 代價就是 前一個專案 那個太吵的坑。

三、形態 A／B（M4 要打分決定的兩個原型）

兩者共用同一份 IconState，只換 IconRenderer 實作 —— 所以做兩個原型的邊際成本很低，值得用證據決定而不是猜。以下都套用新的注意力預算語言。
