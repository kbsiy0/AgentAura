2. 元件切分 誰負責什麼、誰依賴誰

單元做什麼怎麼用依賴
RGBA / IconPalette 新四個狀態各一色 ＋ idle 色；.default 取自 macOS 深色 system palette 的固定值palette[.waiting]無
AppearancePolicy 改多一個 palette 參數（預設 .default），把顏色解析進 IconAppearance.color既有呼叫點不變（有預設值）IconPalette
AnimationCurve 新LEDStripView.alpha(for:phase:) 原封搬到 AuraCore兩個 view 都呼叫它IconAnimation
IconDrawing 新renderer 對「畫」的最小契約：收 appearance＋phase、報寬度StatusItemController 只認這個AppKit
LEDStripView 改加底板、顏色改吃 appearance.color、conform IconDrawing—IconDrawing
HaloView 新B2 畫法—IconDrawing
IconForm 評後刪啟動時讀 UserDefaults 決定建哪個 view；預設 .ledStripdefaults write io.agentaura.app AgentAuraIconForm halo 再重啟Foundation
兩個設計選擇
① 顏色解析放 AppearancePolicy（AuraCore），不放 view：兩個 renderer 不各自查表、顏色邏輯可單元測試、Change 2 換調色盤時 view 一行不用改。
② 預設色是固定 RGBA，不是 NSColor.systemX 的深淺自適應：A2 有底板、背景已固定，自適應沒意義；B2 用深色 palette 值在淺 bar 上也夠亮（mockup §1 淺色那條可對照）。代價：放棄系統色的自動翻轉——這是 R9「簡單」換來的。Change 2 使用者自選色本來就是固定值，兩者一致。

4. A2 底板規格

參數值理由
底板矩形燈條 bounds 外擴 x 4pt、y 3pt；圓角 5ptmockup §2 的比例
底板色固定 rgba(20,20,22,0.82)，深淺模式一律「一律深殼」讓四色永遠疊同一背景；淺模式偏重是已知代價，交 persona 判
底板描邊0.5pt rgba(255,255,255,0.10)淺 bar 上邊緣不糊
status item 寬度preferredWidth + 8 → 由 view 自報，含底板現在寫死 LEDStripView.preferredWidth + 8，改問 IconDrawing
LED 顏色／alpha顏色 = appearance.color；alpha = AnimationCurve.alpha不再自己 switch activity
idleLED 用 palette 的 idle 色（極暗灰），底板照畫底板恆在，「app 活著」有個錨點；idle 燈近乎不可見維持原設計

§4 OK？（特別是「idle 也畫底板」——另一個選擇是 idle 時整個不畫，menu bar 完全乾淨）

5. B2 光環規格

參數值理由
幾何外環直徑 14pt、線寬 1.5pt；核心直徑 6pt；同心mockup §3 B2
顏色環與核心同色 = appearance.color單一訊號
動畫只有環套 AnimationCurve.alpha；核心 alpha 固定 1.0餘光抓「環在動」，核心保住「有東西在」；working 的低對比呼吸只在環上，更安靜
idle環與核心都用 idle 色、alpha 0.35與 A2 idle 同等存在感
status item 寬度14 + 8—
無底板—B 的假設是「像素少、像系統 icon」；要底板就沒有存在理由（mockup §3 註）

7.3 評分維度（每 persona 對兩形態各打 0–10）

餘光辨識 · 遠距辨識 · 不辨色可分 · 常態安靜 · 系統協調 · 資訊清晰。加權信心指數 = Σ(persona 權重 × persona 平均分)。

7.4 決策規則（寫死，不事後解釋）

  1. 信心指數高者勝
  2. 差距 < 0.5（10 分制）視為平手 → 取 P2 不辨色可分 高者（可及性優先）
  3. 仍平手 → 取程式碼較少者（R9）
  4. 贏家指數 < 6.0 → 不選，回 brainstorm（表示兩個都不夠好，可能要 A3/B3）

8. 測試策略 T01 先行：對抗式 double ＋ composition smoke

Gate層守什麼Mutation（改壞 → 幾秒內紅）
paletteCoversEveryActivityAuraCoreIconPalette.default 對 Activity.allCases 每一個都有值——從型別推導，不列舉刪掉 default 裡一個 key → <1s
appearanceCarriesPaletteColorAuraCore對每個 activity，appearance.color == palette[activity]；換一個非預設 palette 也成立AppearancePolicy 寫死回 default → <1s
animationCurveBoundariesAuraCorephase 0／0.5／1 的 alpha；double blink 的四個窗口邊界；breathe 對稱改 0.14 → 0.15 → <1s（這段從 view 搬出來的唯一理由就是讓它可測）
renderersDrawEveryActivityWithoutCrashApp兩個 view 對 5 個 activity × phase {0, .5} 離屏繪製到 NSBitmapImageRep，無 crash、有非透明像素view 的 draw 提早 return → <2s
plateGuaranteesContrast（對抗式）AppA2 離屏繪製，取 LED 中心像素與底板像素，WCAG 相對亮度對比 ≥ 3:1，四色都要——這條直接對應今天的紅字底板 alpha 改 0.0 → 藍色那組紅 <2s
iconFormSelectionIsWiredApp smoke設 UserDefaults 為 halo → StatusItemController 建的是 HaloView；設 led → LEDStripView。tested ≠ wired 的守門IconForm 讀完不用 → <2s
既有 31 條 R4 測試AuraCore不動、必須繼續綠—
既有 isolation gate—RGBA／IconPalette／AnimationCurve 不得載入 AppKit——編譯器 gate 自動涵蓋新檔已有
去相關化：plateGuaranteesContrast 是這個 change 唯一「語意不同於樂於配合 fixture」的關卡——它不問「有沒有畫」，問「畫出來看得見嗎」，用數字（3:1）取代肉眼。刪輸家的 task 要一併刪它對應的 view 測試，並確認贏家的測試仍在。
